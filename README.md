# Tempolab Marketplace (SmartketPlace / "La Place de Marché")

A members-only marketplace for a network of associations. Members list
products and services; other members request them; the seller
accepts or declines. There is no real payment or checkout — an
`Order` is a **reservation/request**, and buyer and seller arrange the
actual exchange off-platform. The UI is entirely in French.

New member accounts require admin approval before they can sign in.

## Tech stack

- **Framework**: Next.js 16 (App Router), React 19, JavaScript (no TS in app code)
- **Database**: PostgreSQL (Neon serverless), via Prisma 7 with the Neon adapter
- **Auth**: NextAuth v5 (beta), Credentials provider (username or email + password), JWT sessions
- **Styling**: Tailwind CSS 4
- **File storage**: Vercel Blob (product images)
- **Email**: Resend (password reset, notifications)
- **Validation**: Zod (`lib/validation.js`)

## Prerequisites

- **Node.js** 20+ and npm.
- **A PostgreSQL database.** Pick one of the two setups below (Option
  A: fully local; Option B: Neon + Vercel). Either works for `npm run dev`.

## Environment variables

Copy [.env.example](.env.example) to `.env.local` (gitignored) and
fill in real values:

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string, used by Prisma |
| `AUTH_SECRET` | NextAuth v5 JWT signing secret (generate with `openssl rand -base64 32`) |
| `BLOB_READ_WRITE_TOKEN` | Vercel Blob token for product image uploads |
| `RESEND_API_KEY` | Resend API key for transactional email |
| `RESEND_FROM_EMAIL` | "From" address for outgoing email |
| `NEXT_PUBLIC_APP_URL` | Public base URL, used in emailed links |

`.env.example` is the only env file committed to the repo — `.env`,
`.env.local`, etc. are gitignored. Keep `.env.example` up to date
whenever you add/remove/rename an environment variable.

## Option A — Fully local (Postgres via apt)

Use this if you don't want any external dependency and just want the
app to run on your machine. Tested on Debian/Ubuntu.

### 1. Install PostgreSQL

```bash
sudo apt-get update
sudo apt-get install -y postgresql postgresql-contrib
sudo systemctl enable --now postgresql
```

Verify it's running:

```bash
sudo systemctl status postgresql
```

### 2. Create the app's database and user

```bash
sudo -u postgres psql -c "CREATE USER kultura WITH PASSWORD 'kultura';"
sudo -u postgres psql -c "CREATE DATABASE kultura OWNER kultura;"
```

### 3. Configure the app

```bash
cd tempolab-marketplace
npm install                 # also runs `prisma generate` via postinstall
cp .env.example .env.local
```

Edit `.env.local` and set:

```
DATABASE_URL="postgresql://kultura:kultura@localhost:5432/kultura"
AUTH_SECRET="<output of: openssl rand -base64 32>"
```

Leave `BLOB_READ_WRITE_TOKEN`, `RESEND_API_KEY`, `RESEND_FROM_EMAIL`
empty — image upload and email will just fail gracefully when unused;
everything else works without them.

> `lib/prisma.js` uses the Neon serverless driver
> (`@prisma/adapter-neon`), but it speaks plain Postgres wire protocol
> underneath, so it connects to a local Postgres instance the same
> way — no code changes needed.

### 4. Create the schema and run

```bash
npx prisma migrate deploy    # applies prisma/migrations to the local DB
npm run create-admin -- admin admin@example.com yourStrongPassword
npm run dev                    # http://localhost:3000
```

To inspect/reset the local DB later:

```bash
npx prisma studio             # browse data in a GUI
sudo -u postgres psql kultura  # raw SQL shell
```

## Option B — Neon (database) + Vercel (hosting)

Use this to test against the same managed services the app is meant
to run on in production, without installing anything locally besides
Node.

### 1. Create a Neon database

1. Sign up / log in at [neon.tech](https://neon.tech).
2. Create a new project (any name/region), e.g. `tempolab-marketplace`.
3. On the project dashboard, copy the **pooled connection string**
   (Connection Details → make sure "Pooled connection" is selected).
   It looks like:
   ```
   postgresql://<user>:<password>@<host>/<dbname>?sslmode=require
   ```

### 2. Apply the schema to Neon

Locally, with Node installed:

```bash
cd tempolab-marketplace
npm install
cp .env.example .env.local
```

Paste the Neon connection string into `.env.local` as `DATABASE_URL`,
then run:

```bash
npx prisma migrate deploy
```

This creates all tables/enums on the Neon database (no local Postgres
needed — Prisma connects straight to Neon over the network).

### 3. Create a Vercel project

1. Push this repo to GitHub (if not already).
2. Go to [vercel.com](https://vercel.com) → **Add New → Project** →
   import the GitHub repo.
3. Framework preset should auto-detect **Next.js**.
4. Before deploying, add the environment variables (Project Settings
   → Environment Variables, or during import): same keys as
   `.env.example` —
   `DATABASE_URL` (the Neon string from step 1), `AUTH_SECRET`,
   `BLOB_READ_WRITE_TOKEN`, `RESEND_API_KEY`, `RESEND_FROM_EMAIL`,
   `NEXT_PUBLIC_APP_URL` (set to the Vercel deployment URL, e.g.
   `https://your-app.vercel.app`).
5. **Vercel Blob**: in the Vercel dashboard, go to **Storage → Create
   Database → Blob**, attach it to the project — this auto-populates
   `BLOB_READ_WRITE_TOKEN` for you (Vercel's Neon integration under
   **Storage → Create Database → Postgres (powered by Neon)** can
   similarly auto-populate `DATABASE_URL` instead of doing step 1
   manually, if you prefer).
6. Click **Deploy**.

### 4. Bootstrap an admin

You need `DATABASE_URL` pointed at the same Neon DB locally (from
step 1/2) to run the one-off script:

```bash
npm run create-admin -- admin admin@example.com yourStrongPassword
```

Then log in on the deployed Vercel URL, or run `npm run dev` locally
against the same Neon `DATABASE_URL` to test before deploying.

### API routes (`app/api/`)

| Route | Purpose |
|---|---|
| `auth/[...nextauth]` | NextAuth handlers |
| `register` | Member signup (creates a `PENDING` Member) |
| `forgot-password`, `reset-password` | Password reset flow |
| `products`, `products/[id]`, `products/batch` | Product CRUD |
| `orders`, `orders/[id]` | Create/update reservation requests |
| `upload` | Authenticated image upload to Vercel Blob |
| `admin/members/[id]` | Admin approve/reject/edit a member |
| `health` | Health check |

## Data model (`prisma/schema.prisma`)

- **Member** — a user account. `role`: `MEMBER` \| `ADMIN`. `status`:
  `PENDING` \| `APPROVED` \| `REJECTED` (gates login). `accountType`:
  `INDIVIDUAL` \| `COMPANY`.
- **Product** — listed by a Member. `type`: `PHYSICAL` \| `DIGITAL` \|
  `SERVICE`. Has price/currency, category, location, quantity, and
  optional shipping info.
- **Order** — a buyer's request for a product. `status`: `PENDING` →
  `ACCEPTED`/`DECLINED` → `COMPLETED`/`CANCELLED`. Represents intent to
  transact, not a payment.
- **PasswordResetToken** — short-lived tokens for the reset-password flow.
- **ActivityLog** — audit trail of important actions (signups, admin
  approvals, product/order changes), indexed by action and date.
- **ErrorLog** — server errors captured automatically via
  `instrumentation.js`'s `onRequestError` hook, used as a lightweight
  in-app error tracker (surfaced under `app/admin/monitoring`).

## Auth flow

1. A visitor signs up (`/signup` → `api/register`), creating a
   `Member` with `status: PENDING`.
2. An admin reviews and approves/rejects them under
   `/admin/membres` (→ `api/admin/members/[id]`).
3. The member logs in (`/login`) with username or email + password.
   `auth.js` throws typed errors (`pending-approval`,
   `account-rejected`) if the account isn't `APPROVED`.
4. Sessions are JWT-based (NextAuth v5, Credentials provider).
